## Evidências locais

- Compilação e verificação TypeScript sem erros.
- Três testes locais aprovados: fluxos da API e portal, proteções HTTP e limites, autenticação da criptografia do backup.
- Sete testes PostgreSQL aprovados: recuperação e limites compartilhados; privilégios restritos; migração e concorrência; importação/rollback; API relacional; sessões; API pela entrada serverless.
- Dependências de produção: `pnpm audit --prod --json` retornou zero avisos conhecidos em 14 dependências contabilizadas. Isso é uma consulta pontual, não certificação de segurança.
- Prettier aprovado nos arquivos alterados.

Os testes usam dados fictícios e schemas descartáveis. Não foi feita restauração em produção. O runner final encerrou com código zero e os processos de diagnóstico desta tarefa foram encerrados.

## Limitações conhecidas

A camada de compatibilidade ainda carrega dados de todos os profissionais dentro do processo da API antes da filtragem, e não há RLS por profissional. Os testes verificam o limite HTTP, não uma fronteira por usuário dentro do banco. O limite por IP pode afetar usuários que compartilham rede e não substitui proteção contra ataques distribuídos. Os contadores guardam hash determinístico do endereço por uma janela curta; continuam sendo informação pseudonimizada e não dado anônimo. Não há MFA no login do aplicativo.

O histórico de auditoria funcional mantém até 500 eventos, e logs do provedor têm retenção própria. Backups preservam hashes de senha e dados clínicos criptografados; exigem controle de acesso e política de retenção. A política de privacidade é rascunho e o projeto continua destinado a avaliação com dados fictícios.
