# Inventário de rotas — baseline atual

Fonte: handlers em `apps/api/src/server.js`, suíte em `apps/api/test/application.test.js` e interface estática. Inventário verificado em 2026-10-29. A API é um `node:http` monolítico; caminhos não listados sob `/api/` terminam em 404 (ou 401 antes do roteamento funcional se não houver sessão). Valores clínicos citados abaixo são categorias de dados possíveis, não dados do store.

## Convenções

- Sessões profissionais (`nc_session`) e de pacientes (`nt_patient_session`) são tokens em `Map` de processo; cookie tem `HttpOnly`, `SameSite=Strict`, `Path=/` e `Max-Age=28800`, `Secure` somente em `NODE_ENV=production`.
- `owned()` compara simultaneamente ID do recurso e `userId`; criações verificam propriedade do paciente. O portal vincula conta a paciente/profissional e retorna DTO restrito a planos publicados.
- JSON inválido gera 400, corpo acima de 1 MB gera 413; erros inesperados viram 500 genérico. Validação de campos varia por rota.
- “Cobertura atual” significa que existe um único teste de integração no repositório; ele não cobre a maioria das rotas abaixo.

## Arquivos estáticos e demais respostas

GET `/`, `/paciente`, `/paciente/ativar`, `/paciente/redefinir`, e arquivos em `apps/web/public` são servidos sem sessão, com CSP e proteção contra traversal lexical. Há assets HTML/CSS/JS. Caminhos inexistentes retornam 404; travessia bloqueada retorna 403. Métodos diferentes de GET para esses arquivos não têm handler explícito de método e podem ainda receber arquivo. Rotas API em método/caminho não suportado retornam 404 para sessão profissional válida; sem sessão, 401 ocorre antes do 404. A API não declara CORS nem rate limiting.
